Модуль Parsec — тестирование триггеров интеграции

Справочник по REST-API и Minion-таску для проверки срабатывания триггеров интеграции Артонит → Parsec.

Версия: 1.0 Дата: 2026-09-16 Модуль: parsec Платформа: Kohana 3.3 · Minion · Firebird

1. Архитектура

Тестирование построено на трёх слоях. Логика живёт только в модели, контроллер и таск — тонкие обёртки вокруг неё.

┌─────────────────────────────────────────────────────────────┐
│                    Model_ParsecTest                         │
│  • Вся SQL-логика                                           │
│  • Вся валидация                                            │
│  • Все коды ошибок                                          │
│  • Возвращает ассоциативные массивы, никакого вывода        │
└─────────────────────────────────────────────────────────────┘
              ▲                               ▲
              │                               │
┌─────────────┴──────────────┐   ┌────────────┴──────────────┐
│  Controller_ParsecTest     │   │  Task_parsecTestTriggers  │
│  • Разбор URL              │   │  • Читает сценарий        │
│  • _param() POST → query   │   │  • Подстановка {…}        │
│  • _to_utf8() + JSON       │   │  • Печать в консоль       │

2. Установка

2.1. Роут

В modules/parsec/init.php (в конец файла):

Route::set('parsectest', 'parsectest(/<action>)')
    ->defaults(array(
        'controller' => 'ParsecTest',
        'action'     => 'index',
    ));

2.2. Модуль подключён

Kohana::modules(array(
    // ...
    'parsec' => MODPATH.'parsec',
    // ...
));

2.3. Структура БД

Модель предполагает наличие полей GUID в PEOPLE и ORGANIZATION.

SELECT COUNT(*) FROM RDB$RELATION_FIELDS
WHERE RDB$RELATION_NAME = 'PEOPLE'
  AND RDB$FIELD_NAME = 'GUID';

Если 0 — добавьте:

ALTER TABLE PEOPLE ADD GUID VARCHAR(50);
ALTER TABLE ORGANIZATION ADD GUID VARCHAR(50);

2.4. BAT-файл

modules/parsec/classes/Task/parsecTestTriggers.bat:

@echo off
chcp 1251 > nul
c:\xampp\php\php.exe c:\xampp\htdocs\city\modules\minion\minion --task=parsecTestTriggers %*

3. REST API

Базовый URL: http://<host>/city/parsectest

3.1. HTML-форма

GET /parsectest — открывает страницу с формами для каждого шага.

3.2. Формат ответа

{
  "ok": true,
  "operation": "add_org",
  "id_org": 4425,
  "guid": "TEST-ORG-1",
  "cardindev_new": [
    {
      "id_cardindev": 881130,
      "operation": 5,
      "id_card": "TEST-ORG-1",
      "id_pep": 1,
      "attempts": 0
    }
  ]
}

При ошибке:

{
  "ok": false,
  "error": "106 Параметры name и guid обязательны",
  "status": 400
}

3.3. Методы

POST /parsectest/add_org

ПараметрОбяз.Описание
nameДаНазвание организации
guidДаGUID организации
parent_guidНетGUID родителя (по умолчанию — корень, id_parent=1)

Ожидаемая операция в CARDINDEV: 5

POST /parsectest/add_person

ПараметрОбяз.Описание
surnameДаФамилия
nameНетИмя
patronymicНетОтчество
guidДаGUID персоны
org_guidДаGUID организации (модель сама найдёт id_org)
tabnumНетТабельный номер

Ожидаемая операция: 3

POST /parsectest/add_card

ПараметрОбяз.Описание
pep_guidДаGUID персоны
cardДаНомер карты в десятичном виде (1..232)

Ожидаемая операция: 9

POST /parsectest/add_access

ПараметрОбяз.Описание
pep_guidДаGUID персоны
accessname_idДаid_accessname (целое > 0)

Ожидаемая операция: 7

Внимание! Триггер PARSEC_07_SS_ACCESSUSER_AI0 срабатывает только если у персоны уже есть активная RFID-карта. Выдавайте карту до категории доступа.

GET /parsectest/status

Последние N записей CARDINDEV. Параметр limit (по умолчанию 20, максимум 500).

POST /parsectest/cleanup

Удалить тестовые данные. Параметр prefix (по умолчанию TEST-). Удаляются CARD, SS_ACCESSUSER, PEOPLE, ORGANIZATION и всё, что наросло в CARDINDEV.

3.4. Примеры curl

# Создать организацию
curl -X POST http://localhost/city/parsectest/add_org \
     -d "name=TEST-ORG-1&guid=TEST-ORG-1"

# Создать персону
curl -X POST http://localhost/city/parsectest/add_person \
     -d "surname=Тестов&name=Иван&guid=TEST-PEP-1&org_guid=TEST-ORG-1"

# Выдать карту
curl -X POST http://localhost/city/parsectest/add_card \
     -d "pep_guid=TEST-PEP-1&card=7419840"

# Выдать категорию доступа
curl -X POST http://localhost/city/parsectest/add_access \
     -d "pep_guid=TEST-PEP-1&accessname_id=64"

# Статус
curl "http://localhost/city/parsectest/status?limit=5"

# Очистка
curl -X POST http://localhost/city/parsectest/cleanup \
     -d "prefix=TEST-"
↑ к оглавлению

5. Сценарии

5.1. Формат шага

array(
    'id'          => 'org',
    'description' => 'Добавить организацию',
    'action'      => 'add_org',
    'params'      => array(
        'name' => 'TEST-ORG-{suffix}',
        'guid' => 'TEST-ORG-{suffix}',
    ),
    'expect_ops'  => array(5),
)

5.2. Плейсхолдеры

ПлейсхолдерЗначение
{suffix}Уникальный суффикс запуска
{ts}time()
{uniq}uniqid()
{cardnum}Случайный номер карты (1..0xFFFFFF)
{ctx.<id>.<field>}Поле field из ответа шага id

5.3. Рекомендуемый порядок шагов

org → people → card → access

Порядок card до access критичен: триггер 7 срабатывает только когда у персоны есть активная RFID-карта.

8. Диагностика

8.1. Типовые проблемы

СимптомПричинаЧто делать
ПРОВАЛ. Ожидалось: [7], получено: [] на шаге access Триггер 7 не сработал: нет активной карты или категория не привязана к Parsec Поменять порядок шагов (card → access), проверить accessname_id
Пустой ответ, ошибка "Не JSON" json_encode вернул false из-за не-UTF8 Проверить _to_utf8() в контроллере
106 при заполненной форме Параметры не дошли до _param() Debug::vars в before() контроллера
409 GUID занят В БД уже есть запись с таким GUID Использовать уникальный суффикс ({suffix})
409 Карта уже выдана Номер карты совпал с существующим Использовать рандомный номер
Кириллица как РџСЂРёРІРµС‚ в консоли Консоль в CP866, файл в CP1251 chcp 1251 перед запуском
