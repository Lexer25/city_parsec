Модуль Parsec — тестирование триггеров интеграции

Справочник по REST-API и Minion-таску для проверки срабатывания всех 10 триггеров интеграции Артонит → Parsec.

Версия: 1.3 Дата: 2026-09-17 Модуль: parsec Платформа: Kohana 3.3 · Minion · Firebird
Что нового в 1.3: оглавление слева дополнено всеми подпунктами документа — теперь любой раздел доступен в один клик.

1. Архитектура

Тестирование построено на трёх слоях. Логика живёт только в модели, контроллер и таск — тонкие обёртки.

┌─────────────────────────────────────────────────────────────┐
│                    Model_ParsecTest                         │
│  • Вся SQL-логика                                           │
│  • Вся валидация                                            │
│  • Все коды ошибок                                          │
│  • Возвращает ассоциативные массивы, никакого вывода        │
└─────────────────────────────────────────────────────────────┘
              ▲                               ▲
              │                               │
┌─────────────┴──────────────┐   ┌────────────┴──────────────┐
│  Controller_ParsecTest     │   │  Task_parsecTestTriggers  │
│  • Разбор URL              │   │  • Читает сценарий        │
│  • _param() POST → query   │   │  • Подстановка {…}        │
│  • _to_utf8() + JSON       │   │  • Печать в консоль       │
│  • HTML-форма (index)      │   │  • Сравнение ops          │
└────────────────────────────┘   └───────────────────────────┘
        HTTP / браузер                  CLI / Minion

2. Установка

2.1. Роут

В modules/parsec/init.php (в конец файла):

Route::set('parsectest', 'parsectest(/<action>)')
    ->defaults(array(
        'controller' => 'ParsecTest',
        'action'     => 'index',
    ));

2.2. Модуль подключён

Kohana::modules(array(
    // ...
    'parsec' => MODPATH.'parsec',
    // ...
));

2.3. BAT-файл

@echo off
chcp 1251 > nul
c:\xampp\php\php.exe c:\xampp\htdocs\city\modules\minion\minion --task=parsecTestTriggers %*
Кодировки: JSON-файлы сценариев должны быть в UTF-8 без BOM.

3. REST API

Базовый URL: http://<host>/city/parsectest

3.1. Общий формат ответа

Успешный ответ (HTTP 200)

{ "ok": true, "operation": "<имя_операции>", ..., "cardindev_new": [ ... ] }

Ответ с ошибкой (HTTP 400/404/409/500)

{ "ok": false, "error": "<номер> <текст ошибки>", "status": 400 }

Служебные поля ответа

ПолеТипВсегдаОписание
okboolДаtrue при успехе, false при ошибке
operationstringПри успехеИмя операции
errorstringПри ошибкеТекст ошибки с номером
statusintПри ошибкеHTTP-статус ошибки

Вложенный массив cardindev_new

ПолеТипОписание
id_cardindevintПервичный ключ записи
operationintКод операции
id_cardstringGUID / ID карты / ID категории
id_pepintID персоны, если применимо
attemptsintСчётчик попыток (обычно 0)

3.14. Примеры curl

# Создать организацию
curl -X POST http://localhost/city/parsectest/add_org \
     -d "name=TEST-ORG-1&guid=TEST-ORG-1"

# Изменить организацию
curl -X POST http://localhost/city/parsectest/update_org \
     -d "guid=TEST-ORG-1&name=TEST-ORG-RENAMED"

# Удалить организацию
curl -X POST http://localhost/city/parsectest/del_org \
     -d "guid=TEST-ORG-1"

# Создать персону
curl -X POST http://localhost/city/parsectest/add_person \
     -d "surname=Тестов&name=Иван&guid=TEST-PEP-1&org_guid=TEST-ORG-1"

# Изменить персону
curl -X POST http://localhost/city/parsectest/update_person \
     -d "guid=TEST-PEP-1&surname=Изменённый"

# Удалить персону
curl -X POST http://localhost/city/parsectest/del_person \
     -d "guid=TEST-PEP-1"

# Выдать карту
curl -X POST http://localhost/city/parsectest/add_card \
     -d "pep_guid=TEST-PEP-1&card=7419840"

# Удалить карту
curl -X POST http://localhost/city/parsectest/del_card \
     -d "pep_guid=TEST-PEP-1&card=7419840"

# Выдать категорию
curl -X POST http://localhost/city/parsectest/add_access \
     -d "pep_guid=TEST-PEP-1&accessname_id=64"

# Удалить категорию
curl -X POST http://localhost/city/parsectest/del_access \
     -d "pep_guid=TEST-PEP-1&accessname_id=64"

# Статус
curl "http://localhost/city/parsectest/status?limit=5"

# Очистка
curl -X POST http://localhost/city/parsectest/cleanup -d "prefix=TEST-"

5. Сценарии

5.1. Формат шага

{
    "id": "org",
    "description": "Добавить организацию",
    "action": "add_org",
    "params": {
        "name": "TEST-ORG-{suffix}",
        "guid": "TEST-ORG-{suffix}"
    },
    "expect_ops": [5]
}

5.2. Поля шага

ПолеТипОбяз.Описание
idstringДаИдентификатор шага для {ctx.<id>.<field>}
descriptionstringНетОписание для лога
actionstringДаИмя метода Model_ParsecTest
paramsobjectДаПараметры метода
expect_opsarray<int>НетОжидаемые коды операций в CARDINDEV

5.3. Плейсхолдеры

ПлейсхолдерТипПример
{suffix}string20260917123456_7890
{ts}int1758080876
{uniq}string68cb0d1e4a3b2
{cardnum}intСлучайное 1..16777215
{ctx.<id>.<field>}mixed{ctx.org.guid} → фактический GUID

5.4. Правила JSON

Запятая ставится между элементами, но не после последнего. Файл — в UTF-8 без BOM.

Проверка:

c:\xampp\php\php.exe -r "json_decode(file_get_contents('path/to/file.json')); echo json_last_error_msg(), PHP_EOL;"

6.5. Требования перед запуском

1. accessname_id = 64 должен быть привязан к Parsec. Иначе триггеры 7 и 8 проигнорируют вставку. 
SELECT s.id_server, s.name
FROM accessname an
JOIN access a ON an.id_accessname = a.id_accessname
JOIN device d ON a.id_dev = d.id_dev
JOIN device d2 ON d2.id_ctrl = d.id_ctrl AND d2.id_reader IS NULL
JOIN server s ON d2.id_server = s.id_server
WHERE an.id_accessname = 64;
id_server должен быть 1.
2. Все триггеры активны. 
SELECT RDB$TRIGGER_NAME, RDB$TRIGGER_INACTIVE
FROM RDB$TRIGGERS
WHERE RDB$TRIGGER_NAME STARTING WITH 'PARSEC_'
ORDER BY RDB$TRIGGER_NAME;
Все должны иметь RDB$TRIGGER_INACTIVE = 0.
