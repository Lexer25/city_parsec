Модуль Parsec — задачи сверки

Справочник по четырём Minion-задачам для сверки данных СКУД Артонит и СКУД Parsec.

Версия: 1.0 Дата: 2026-09-14 Модуль: parsec Платформа: Kohana 3.3 · Minion · Firebird

0. Общие сведения

Все четыре задачи — это Minion-таски модуля parsec, запускаются из командной строки через minion. Используют SOAP-клиент Model_Cch (включая mock-режим), работают с БД Артонит через Database::instance('fb'). Лог — табличный, с разделителем табуляции.

Расположение задач

c:\xampp\htdocs\city\modules\parsec\classes\Task\
├── parsecSyncPeope.php           (сверка персон)
├── parsec_sync_identifiers.php   (сверка карт)
├── parsecSyncOrg.php             (сверка дерева организаций)
└── parsecSyncAccessGroups.php    (сверка категорий доступа)

Шаблон запуска

chcp 65001
c:\xampp\php\php.exe ^
    c:\xampp\htdocs\city\modules\minion\minion ^
    --task=<ИМЯ_ЗАДАЧИ> [опции] ^
    > <файл_лога>.log 2>&1
Кодировка логов: все логи пишутся в Windows-1251. Открывайте их в Notepad++ с кодировкой Windows-1251.

1. Сверка персон

Имя задачи parsecSyncPeope
Файл Task/parsecSyncPeope.php
Класс Task_parsecSyncPeope
Что проверяет Наличие персон Артонит в Parsec и совпадение их организации

Что делает

  1. Берёт персон из Артонит (PEOPLE.id_pep > 1, guid не пуст) вместе с их организацией.
  2. По guid персоны вызывает GetPerson(pep_guid) в Parsec.
  3. Если персоны нет — фиксирует НЕТ В PARSEC.
  4. Если есть — сравнивает ORG_ID из Parsec с ORGANIZATION.guid персоны в Артонит.
  5. Через GetOrgUnit получает название организации Parsec (с кэшем).

Задачи интегратору

ОперацияКогда ставится
3 Персоны нет в Parsec — добавить пользователя
35 Организация персоны в Parsec не совпадает с Артонит — изменить данные

Примеры запуска

:: Одна персона, без задач
... --task=parsecSyncPeope --id_pep=4 --add=0 > sync_pep.log 2>&1

:: Первые 100, без задач
... --task=parsecSyncPeope --limit=100 --add=0 > sync_pep.log 2>&1

:: Полный прогон с постановкой задач
... --task=parsecSyncPeope --add=1 > sync_pep_all.log 2>&1

Формат лога

Счётчик  Статус         ФИО                 Artonit                         Parsec                          Примечание

[2/10] id_pep=5 guid=...  OK           Авилкина М. В.  Artonit: <guid> (1 корпус)  Parsec: <guid> (1 корпус)

Статусы: OK РАСХОЖДЕНИЕ НЕТ В PARSEC ПРОПУЩЕН ОШИБКА SOAP ОШИБКА

2. Сверка идентификаторов (карт)

Имя задачи parsec_sync_identifiers
Файл Task/parsec_sync_identifiers.php
Класс Task_parsec_sync_identifiers
Что проверяет Совпадение карт персоны в Артонит и Parsec

Что делает

  1. Берёт персон с их активными RFID-картами (CARD.id_cardtype = 1, ACTIVE > 0).
  2. По каждой персоне вызывает GetPersonIdentifiers(pep_guid).
  3. Приводит обе стороны к единому формату — 8 hex-символов upper:
    • Артонит id_card (десятичное, 7419840) → dechex → 00713490,
    • Parsec CODE (007B4598) — уже hex, нормализуется через str_pad.
  4. Сравнивает множества карт.

Задачи интегратору

ОперацияКогда ставится
9 Карта есть в Артонит, нет в Parsec — добавить
10 Карта есть в Parsec, нет в Артонит — удалить

Примеры запуска

:: Одна персона
... --task=parsec_sync_identifiers --id_pep=7 --add=0 > sync_ids.log 2>&1

:: Массовый прогон без задач
... --task=parsec_sync_identifiers --add=0 > sync_ids_all.log 2>&1

Формат лога

[1/1] id_pep=7 guid=441DC23B-...  OK           Акимова Л.  007B4598  007B4598
[2/1] id_pep=8 guid=...           РАСХОЖДЕНИЕ  Петрова А.  007B4598              + в Артонит: 007B4598

Примечания:

  • + в Артонит: <код> — карта есть в Артонит, нет в Parsec → задача 9
  • - в Parsec: <код> — карта есть в Parsec, нет в Артонит → задача 10

3. Сверка дерева организаций

Имя задачи parsecSyncOrg
Файл Task/parsecSyncOrg.php
Класс Task_parsecSyncOrg
Что проверяет Наличие организаций Артонит в Parsec и совпадение их родителя

Что делает

  1. Берёт организации из Артонит (ORGANIZATION.id_org > 3, guid не пуст) с родителем.
  2. По guid организации вызывает GetOrgUnit(org_guid).
  3. Если организации нет — НЕТ В PARSEC.
  4. Если есть — сравнивает:
    • PARENT_ID в Parsec с ORGANIZATION.guid родителя в Артонит,
    • NAME в Parsec с названием организации в Артонит (опционально).

Задачи интегратору

ОперацияКогда ставится
5 Организации нет в Parsec — добавить
55 Родитель или название расходятся — изменить

Примеры запуска

:: Одна организация
... --task=parsecSyncOrg --id_org=5 --add=0 > sync_org.log 2>&1

:: Массовый прогон
... --task=parsecSyncOrg --add=0 > sync_org_all.log 2>&1

Формат лога

[1/10] id_org=5 guid=...  OK          1 корпус  parent: <guid> (корень)    parent: <guid>
[2/10] id_org=6 guid=...  РАСХОЖДЕНИЕ  2 корпус  parent: <guid> (1 корпус)  parent: <guid>  родитель не совпадает

4. Сверка категорий доступа

Имя задачи parsecSyncAccessGroups
Файл Task/parsecSyncAccessGroups.php
Класс Task_parsecSyncAccessGroups
Что проверяет Категории доступа человека в Артонит vs группы доступа его карт в Parsec

Что делает

  1. Берёт категории персоны из Артонит (SS_ACCESSUSER → ACCESSNAME.guid).
  2. Через GetPersonIdentifiers получает карты персоны в Parsec, у каждой — ACCGROUP_ID.
  3. Учитывает «специальную иерархию» Parsec (ParsecIntegrationDescription_20230113.pdf, стр. 62):
    • эффективный набор групп карты = {ACCGROUP_ID} ∪ GetInheritedAccessGroups(ACCGROUP_ID),
    • объединяет по всем картам персоны.
  4. Оставляет только группы, известные в ACCESSNAME Артонит (отбрасывает синтетические «контейнерные» группы).
  5. Сравнивает множества.

Задачи интегратору

ОперацияКогда ставится
7 Категория есть у человека в Артонит, но отсутствует на его картах в Parsec
8 Категория есть на картах в Parsec, но отсутствует у человека в Артонит
Сверка делается на уровне персоны, как в триггерах PARSEC_07_SS_ACCESSUSER_AI0 / PARSEC_08_SS_ACCESSUSER_AD0. Интегратор сам раскидывает категорию по картам.

Примеры запуска

:: Одна персона
... --task=parsecSyncAccessGroups --id_pep=7 --add=0 > sync_ag.log 2>&1

:: Массовый прогон
... --task=parsecSyncAccessGroups --add=0 > sync_ag_all.log 2>&1

Формат лога

[1/1] id_pep=7 guid=...  OK          Акимова Л.  <guid> (Администраторы)  <guid> (Администраторы)
[2/1] id_pep=8 guid=...  РАСХОЖДЕНИЕ Петрова А.  <guid> (Гости)                               + в Артонит: <guid>

5. Рекомендуемый порядок запуска

При полной сверке порядок важен: сначала организации, потом персоны, потом карты, потом категории.

chcp 65001

:: 1. Организации
c:\xampp\php\php.exe ...\minion --task=parsecSyncOrg --add=1 > log_org.log 2>&1

:: 2. Персоны
c:\xampp\php\php.exe ...\minion --task=parsecSyncPeope --add=1 > log_pep.log 2>&1

:: 3. Карты
c:\xampp\php\php.exe ...\minion --task=parsec_sync_identifiers --add=1 > log_ids.log 2>&1

:: 4. Категории доступа
c:\xampp\php\php.exe ...\minion --task=parsecSyncAccessGroups --add=1 > log_ag.log 2>&1
Правило. Перед массовым прогоном с --add=1 всегда сначала запускайте с --add=0. Убедитесь, что количество расхождений правдоподобно (не «все 4492 персоны»). Если расхождений подозрительно много — почти всегда это означает, что парсер не находит нужное поле в SOAP-ответе.

6. Обработка ошибок и диагностика

Симптом Причина Что делать
Все персоны в «НЕТ В PARSEC» SOAP недоступен, mock отключён, нет сессии Проверить modules/parsec/config/soap.php, mock_mode, доступность WSDL
Все персоны в «РАСХОЖДЕНИЕ + в Артонит» ORG_ID/PARENT_ID/CODE не извлекаются Добавить временный print_r($response) для одной записи, посмотреть реальные имена полей
Все персоны в «ОШИБКА: нет ORG_ID» Ответ GetPerson не содержит ожидаемого поля Смотреть сырой ответ, поправить извлечение
Кракозябры в логе (только ФИО) Файл .php в UTF-8, данные Firebird в CP1251 Пересохранить .php в Windows-1251
(Notepad++: Кодировки → Преобразовать в ANSI)
Кракозябры только в названии организации из Parsec Parsec отдаёт UTF-8, лог в CP1251 Уже обрабатывается через _utf8_to_cp1251. Проверить, что для поля вызван этот хелпер
Слишком много задач при --add=1 Ложные расхождения из-за парсера Остановить, разобраться, удалить лишние задачи из CARDINDEV, перезапустить

Просмотр сырого SOAP-ответа

Временная вставка в соответствующем методе задачи:

static $debug_done = false;
if (!$debug_done) {
    $debug_done = true;
    Minion_CLI::write('=== DEBUG ===');
    Minion_CLI::write(print_r($response, true));
    Minion_CLI::write('=== END ===');
}

Запустить с --id_pep=1 --add=0 --verbose=1 (или --id_org=5) и посмотреть в логе структуру ответа.

7. Mock-режим

В modules/parsec/config/soap.php:

'mock_mode' => true,   // true — работа без реального Parsec

В mock-режиме Model_Cch использует MockSoapClient, который возвращает фиксированные данные. Удобно для отладки логики парсеров и постановки задач — но все персоны/карты/организации будут выглядеть не так, как в реальной системе.

Перед рабочей сверкой mock обязательно выключить: 'mock_mode' => false,

9. Как остановить массовый прогон

Ctrl+C в окне консоли. Все уже созданные задачи в CARDINDEV останутся. Если их надо откатить:

-- Посмотреть, что создалось
SELECT cd.id_cardindev, cd.operation, cd.id_card, cd.id_pep, cd.time_stamp
FROM cardindev cd
WHERE cd.time_stamp >= '2026-09-14'
ORDER BY cd.id_cardindev DESC;

-- Удалить задачи конкретной операции, созданные после определённого времени
DELETE FROM cardindev cd
WHERE cd.operation IN (3, 35)
  AND cd.time_stamp >= '2026-09-14';

-- Или снести всё (аккуратно!)
DELETE FROM cardindev;
Перед удалением — сделайте бэкап таблицы CARDINDEV.
